# Oncology Survival Modelling Masterclass

Interactive, self-contained teaching application for [HEOR Interactive Labs](https://kareemelfass.github.io/HEOR-Interactive-Labs/).

**Launch:** https://kareemelfass.github.io/HEOR-Interactive-Labs/oncology-survival-masterclass/

## Purpose

Develop a defensible understanding of survival endpoint definitions and the explicit transitions in oncology cohort state-transition modelling. The application does not assume that TTP KM represents observed PF state occupancy, and it does not imply that observed early-versus-late progression subgroup PPS differences represent a causal benefit from delaying progression.

## Files

- \`index.html\`: 13-chapter MathJax reference with explanations, worked examples, interactive panels and exercises.
- \`style.css\`: responsive navigation, tables and graphics.
- \`model-core.mjs\`: dependency-free pure calculation functions for competing hazards, conditional PPS and a cohort STM.
- \`lab.js\`: interactive controls, charts, validation, navigation and export.
- \`tests.mjs\`: mathematical and cohort-flow regression tests, runnable with \`node tests.mjs\`.

MathJax is loaded from a CDN; the rest of the lab uses no third-party JavaScript framework. For offline equations, host a local copy of MathJax and change the script URL.

## Calculation conventions

- Hazards are rates per month; \`dt\` is in months.
- Unless stated otherwise, all displayed values are synthetic and illustrative.
- PF first exits are based on constant (or piecewise constant) competing hazards: \`p_leave = 1-exp(-(lambda_progression+lambda_death)*dt)\`, split by each cause's hazard share.
- The live cohort engine has monthly cycles. Newly progressing patients enter PD1 **at the end** of that cycle. They face post-progression mortality starting during the next model cycle.
- A final PD3+ tunnel pools all later durations with a constant monthly conditional death probability set by the user. This is a deliberate *tail extrapolation assumption*.
- History mode groups people progressing on/before the specified integer cycle into early-group tunnels and all later progressions into late-group tunnels. Duration-only mode applies the early PPS inputs to all progressors. Constant mode applies the first early PPS probability throughout.
- OS generated by the STM is (PF + alive PD)/initial cohort; PFS generated by the STM is PF/initial cohort.
- A first-exit progression CIF includes patients who subsequently died after progression. It is **not** current PD occupancy.
- Observed aggregate TTP plus aggregate PPS cannot identify pre-progression death or progression-history-specific PPS.

## Validation

The pure test suite verifies:
- first-exit transition probabilities sum to 1;
- exact formulae match analytically expected numbers;
- a PFS/TTP curve pair yields the correct interval hazards;
- incompatible curves fail loudly rather than silently clipping an invalid death hazard;
- conditional PPS calculations are correct;
- early and late progression get different PPS transition probabilities in history mode;
- both zero-hazard and progression-free boundary cases;
- per-cycle cohort accounting, non-negative health states, and monotone death;
- PSM occupancy identity.

The app itself also displays a conservation check after each simulation.

## Pedagogical limitations

This app is not a calibrated clinical model, HTA submission, automated curve digitizer or causal inference tool. It has no treatment-specific RCT inputs, cost/utility modules or direct data import. For actual model development, confirm progression/event definitions and use appropriate clinical and statistical review before choosing structures or extrapolations.

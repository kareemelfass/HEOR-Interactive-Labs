# ISPOR Europe 2026 Research Atlas

**Live dashboard:** https://kareemelfass.github.io/HEOR-Interactive-Labs/ispor-intelligence/

This independent research tool provides a searchable conference research landscape, source-linked evidence explorer, topic co-occurrence matrix and interactive **knowledge graph (KG)**.

It is **not affiliated with ISPOR**. A graph edge means that a topic was detected in a presentation's metadata/text. It does not mean a method was formally applied, a finding was verified, or a policy was adopted.

## Data provenance

1. **Official ISPOR**: Each verified record links to its original ISPOR Europe 2026 presentation page, when available.
2. **Verified seed**: The small hand-curated subset in data/verified-records.json consists of specific official presentations. The seed knowledge graph is in data/knowledge-graph.json until the automated extraction refresh succeeds.
3. **Full-corpus endpoint**: The app attempts to load the independent ISPOR Europe 2026 Abstract Archive, published at https://justinsyu.github.io/ispor-eu-nov-2026/ (3,097 records in its snapshot collected 24 August 2026). This **is not** a verified final-conference census. Browser loading requires that the source host allows cross-origin access.
4. **Rebuild pipeline**: scripts/build_kg.py converts the archive into metadata only: presentation IDs, titles, official URLs, keyword topic tags, disease signals and graph edges. It deliberately does not republish abstract bodies.

The active source and record count appear at the top of the dashboard. In case the archive cannot be fetched, a prebuilt records-index.json generated by GitHub Actions is used if available. Otherwise the tool shows the clearly labelled verified seed. This prevents a sample from being silently presented as a full corpus.

## Views

- **Landscape:** Multi-label topic signals and disease keyword signals, shown as counts and within-filter percentages.
- **Knowledge graph:** Click a theme to pivot to related presentations and co-mentioned topics; click a presentation to open its official ISPOR page.
- **Evidence explorer:** Full-text search when source abstracts are available, source links and CSV export.
- **Methods & intersections:** Topic co-occurrence matrix.
- **Data & methods:** Provenance statement, quality metrics and limitations.

The **Export KG JSON** button produces a graph from whichever corpus is currently loaded. The repository includes a machine-readable data/knowledge-graph.json, rebuilt by the workflow when the independent source is available.

## How to rebuild

Python 3.10 or newer, standard library only:

    python -m unittest discover -s ispor-intelligence/tests -v
    python ispor-intelligence/scripts/build_kg.py

The pipeline downloads the public JSON and creates:

- data/knowledge-graph.json (topic/presentation nodes and MENTIONS edges)
- data/records-index.json (title, ID, URL, year, theme and disease tags)
- data/summary.json (aggregate counts and metadata)

The builder refuses to replace the published graph if fewer than 1,000 candidate/usable records can be parsed. Its exact input source and record coverage are recorded in the generated files. Import a different JSON locally using the dashboard's Import JSON control.

The GitHub Actions workflow at .github/workflows/ispor-intelligence.yml tests and rebuilds the derived graph on pipeline changes or by manual workflow dispatch. Repository Actions permissions must permit writing contents for automatic commits to succeed.

## Interpretation rules

- Frequency of abstracts **does not measure** conference discussion intensity, attendance or scientific impact.
- A topic tag is a *keyword signal*, not verified methods extraction, an author-endorsed label or a conclusion.
- Presentations can have multiple topic tags. Topic counts do not sum to total presentations.
- A 2026-only dataset cannot establish *trends over time*. Years 2024 and 2025 would need equivalent retrieval and coding.
- A co-mention does not imply causation or equivalence between methods.
- Titles are included for navigation; abstract bodies remain at source. Use the official ISPOR page for exact conclusions and citations.
- Third-party archive content, tagging accuracy, and completeness should be independently audited before scholarly or policy use.

## Tech stack

Static, mobile-responsive HTML/CSS/vanilla JavaScript with an SVG graph. Python standard-library ETL for the derived KG; GitHub Pages hosting. No tokens, API keys, cookies, analytics or build dependencies required in the browser.

## Copyright and attribution

ISPOR and original contributors retain their respective rights in their content. The project links to original records, does not republish full abstracts, and discloses the independent source used for automated indexing.

## Next methodological extensions

Human-validated entity types (study design, methods **actually used**, study findings and limitations), explicit provenance spans, extraction confidence, and harmonised 2024–2026 coverage. Those extensions should not be inferred from present keyword edges.
